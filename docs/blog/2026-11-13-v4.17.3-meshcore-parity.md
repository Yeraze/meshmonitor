MeshMonitor 4.17.3 is out. Most of it brings MeshCore up to the level Meshtastic already had, using one shared code path for both protocols where they overlap. It also fixes a channel-secret leak in the v1 API and a cross-source backup read, and it adds an opt-in filter for spam in node names.

Read the [upgrade notes](#upgrade-notes) before you update. A few defaults changed.

## Security fixes

- **MeshCore channel secrets in the v1 API.** The API returned a channel's `psk` to any caller who could read messages. It now returns the secret only to admins and to users with write access to that channel.
- **Source delete removes secrets.** Deleting a source now removes its MeshCore device key and channel secrets.
- **Device backups are per source.** A user with configuration read access on one source could download another source's backup, channel keys included. Backups now need `configuration:write` on the source, files are written readable only by the server, and Meshtastic backups no longer store the node's private key.
- **Gateway membership and notifications.** Dashboard gateway data needs packet monitor access, and a mention alert no longer leaks channel text opened with another source's key.
- **Bridge dependency.** The bridge uses msgpack 1.2.3, which fixes CVE-2026-114613.

## Node-name anti-spam

Some people put invite links in their node names. Turn on **Global Settings, Security, Node name anti-spam** and MeshMonitor replaces those links with `[spammer]` before it stores the name. It works on every source and protocol, never changes your own node, and sends nothing on air. You can add your own hosts or patterns and re-scan names you already hold. It is off by default. See [Security](/features/security#node-name-anti-spam).

## MeshCore

- **Settings and security.** Repeater and Room Server settings forms (local and remote), a Security tab with dead contacts, path-hash collisions, advert signatures and clock-offset checks, and per-source device backups.
- **Notifications.** Message, server-event and trace alerts, a clock-out-of-sync alert, new-neighbour alerts, and a Notifications tab for MQTT region feeds.
- **Automation.** Auto Welcome, Auto Favorite, Auto Delete by Distance, Time Sync and Remote Telemetry sections, long-message splitting, and timers that send to several channels.
- **Resend and heard-by.** Pick the repeaters that must relay a channel message before the Resend button clears, with an Any or All rule.
- **MeshCore One contact tokens.** Import a contact from a message in one click, and share a contact from the composer.
- **Rooms.** Selecting a room no longer logs in. Saved posts show read-only, and you press **Login** to post or fetch more.
- **Map and lists.** Shared map layers, Map Analysis, estimated positions, node and DM list sort, filters and export, and Traceroute Explorer support for MeshCore traces.

## Dashboard and MQTT

- **Fixed Y-axis range.** A ruler button on a telemetry chart sets a fixed minimum and maximum. See [Telemetry widgets](/features/telemetry-widgets#fixed-y-axis-range).
- **Root topic finder.** A subscribe-only sample of an MQTT broker suggests root topics near you, with an offline place lookup and a MeshCore IATA region finder. See [Finding a root topic](/features/mqtt-setups#finding-a-root-topic).
- **Fixed position by map pin** for Meshtastic and MeshCore, and **`BIND_ADDRESS`** to choose the address the server binds to.

## Fixes worth knowing

- Queued channel sends no longer report a false "ACK timeout" after the radio sent them.
- One failing poll section no longer blanks the node and channel lists.
- Restoring a backup skips columns the target table lacks, and the first boot after a restore keeps the old telemetry. The MySQL backup list loads again.
- MeshCore pages work in phone landscape, and a source that is not connected shows a clear notice.

## Upgrade notes

- Migrations 223 to 232 run on start. Back up your database first.
- **Rooms:** selecting a room no longer logs in. Press **Login**.
- **Automatic-trace notifications** have a new toggle, off by default. Traces you start still notify.
- **MeshCore timers** send to at most 4 channels, 10 seconds apart.
- **Security digest:** `POST /api/security/digest/send` needs a `sourceId`. Sources that share the global Apprise URL get one combined daily digest, and an install with a global URL starts to receive MeshCore digests.
- **Device backups** need `configuration:write` on the source. Older backup files keep the private key; delete them if that matters to you.
- **MeshCore DM alerts:** existing push subscribers start to receive DM and room-post alerts. Turn them off per source on the Notifications tab.

The full list is in the [changelog](https://github.com/Yeraze/meshmonitor/blob/main/CHANGELOG.md).
